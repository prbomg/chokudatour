# Миграции базы данных

Структура базы хранится в `migrations.php`. Каждая миграция имеет последовательный номер, название и функцию `up`. Применённые номера записываются в таблицу `schema_migrations` вместе с датой выполнения.

При обычном открытии приложения неприменённые миграции запускаются автоматически из `db.php`. Если структура актуальна, страницы не выполняют `CREATE TABLE` и `ALTER TABLE`. Ошибка миграции больше не скрывается: загрузка останавливается с номером и названием неудавшейся миграции.

Для ручной проверки и обновления из каталога приложения доступны команды:

```sh
php migrate.php status
php migrate.php up
```

`status` завершится с кодом 1, если есть неприменённые версии. `up` применит их по порядку. На MySQL обновление защищено общей блокировкой, поэтому два одновременных запроса не запускают одну миграцию параллельно.

Перед миграцией рабочей базы следует сделать резервную копию. Уже выпущенные миграции не редактируются: следующее изменение схемы добавляется новым номером в `applicationMigrations()`. Откат структуры выполняется восстановлением резервной копии; автоматические `down`-миграции намеренно не запускаются, чтобы не удалить рабочие данные по ошибке.
